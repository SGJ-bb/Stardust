# 无障碍 vs shell：AI 操作手机到底需要哪个

> 结论：**「让 AI 替你操作手机」90% 靠无障碍就够了，且零门槛（不用电脑、不用 Shizuku、不用配对码）。**
> shell 只在少数"系统级动作"上不可替代，属于锦上添花。

## 能力对照

| 你想要的效果 | 无障碍 | shell（Shizuku / adb） |
|---|---|---|
| 看懂界面（文字、按钮、输入框） | ✅ UI 树 | ✅（dumpsys 更底层） |
| 点击 / 长按 / 滑动 / 输入文字 | ✅ `dispatchGesture` + `ACTION_SET_TEXT` | ✅ `input` |
| 返回 / 主页 / 最近任务 / 通知栏 | ✅ `performGlobalAction` | ✅ |
| 截屏 | ✅ `takeScreenshot`（API 30+，**不需要**投屏授权） | ✅ `screencap` |
| 启动别的 App / 打开设置页 | ✅ 用 Intent 或点桌面图标 | ✅ `am start` |
| 读通知、回消息 | ✅ 配通知使用权 | ⚠️ 不如无障碍直接 |
| 改系统设置（勿扰、字体、亮度…） | ⚠️ 只能"打开设置页让用户点" | ✅ `settings put` |
| 静默授权别的应用 | ❌ | ✅ `pm grant` |
| 强停别的 App | ⚠️ 可以从最近任务划掉 | ✅ `am force-stop` |
| 改系统级开关（移动数据、飞行模式） | ❌ | ⚠️ 部分 ROM 仍限制 |
| 读写别的 App 私有数据 | ❌ | ❌（shell 也读不到） |

**表格里"❌/⚠️"的那几行，才是你为了它去折腾 shell 的理由。** 剩下的全都能用无障碍解决，而无障碍只需要在系统设置里点一下开关——**不碰电脑**。

## 三条路的真实成本

| 方案 | 要不要电脑 | 要不要装东西 | 覆盖能力 | 我的工作量 |
|---|---|---|---|---|
| **A. 无障碍（已完成）** | ❌ 不用 | ❌ 不用 | 上表 90% | 0（已能用） |
| **B. 装一次 Shizuku** | ❌ 不用（用配对码） | ✅ 装一个 App | 上表 100% | 0（已对接） |
| **C. 自研配对（P1）** | ❌ 不用 | ❌ 不用 | 上表 100% | 1~2 天 + 真机联调，需参考源码对齐 |

注意 B 和 C 的差别只有"**用户装不装那一个 App**"，能力完全一样；而 C 的代价全在"重写别人已经写好的密码学"。

## 建议的顺序

1. **先只用无障碍跑一轮真实任务**（点外卖、回微信、改设置）。如果 90% 场景够用，就别为最后 10% 付 1~2 天成本；
2. 真碰到"必须 `settings put` / `pm grant`"的场景，再装一次 Shizuku（配对码，30 秒）；
3. 如果你就是不想装任何东西、也不想付这个成本 —— 那最后 10% 的能力就先放下，
   等将来拿到 AOSP 源码我再把 P1 补齐（协议是通用的，做一次全机型可用）。

## 关于"配对是通用协议"的证据

- 协议在 `packages/modules/adb/pairing_auth/`（SPAKE25519 + 16 字节口令 → PSK）；
- 传输在 `pairing_connection/`（TLS-PSK，`TLS_PSK_WITH_AES_128_GCM_SHA256`）；
- 通道内用 `PairingPacket` 交换公钥（`adb.rsa.publickey`）。

这套代码被所有 Android 11+ 机型共享，**不存在"按厂商分别实现"**。
