# 摸清一个陌生 App

## 第一步：看清它是什么类型（一条命令）

```
device {"action":"launch","package":"包名"}
device {"action":"ui_tree"}
```

看返回的**两个数**：

| 情况 | 判断 | 怎么办 |
|---|---|---|
| 有几十个节点、带文字、有可点元素 | 正常原生 App | 继续往下走 |
| 节点数不多（30~50）但**有真元素**：文字、EditText、按钮都在 | 可以操作，别被数量骗了 | 继续往下走，小红书、知乎都是这种 |
| 只有个位数节点、界面明明很丰富 | 自绘框架（Flutter/Compose） | **别调参数了**，直接告诉用户"这个界面我读不到内容" |
| 只有 2 个节点，写着"输入密码访问" | 系统应用锁 | 停下来让用户自己解锁 |
| 页面名带 Login | 没登录 | 先登录，或只做到登录前 |

**包名怎么来**：`device {"action":"app_list","filter":"关键词"}` 查。

## 第二步：找稳定抓手（按可靠性排）

同一个界面上，元素的几种标识可靠性差很多：

1. **资源 id**（形如 `#search_bar`）—— 最稳，跨版本不变
2. **内容描述**（`desc=「搜索」`）—— 次稳，图标按钮通常有
3. **文字**—— 能用，但文案会改、同名的可能有好几个
4. **坐标**—— 最后手段，布局一变就废

记技能的时候**优先记 id**，没有 id 再记文字。

## 第三步：摸主干（三步就够）

不用把整个 App 都摸一遍，只摸"从首页到目标"这条线上的东西：

1. **底部 tab**：几乎所有 App 都是「首页 / 发现 / 消息 / 我的」，先记下名字和位置
2. **顶部搜索栏**：多数 App 的万能入口，一个搜索框能到大部分内容
3. **目标页的关键按钮**：比如详情页的「播放」「评论」「点赞」

**不要逐个点开每个 tab 看** —— 那是浪费步数。需要哪个再点哪个。

## 第四步：验证你的判断

每记下一个元素，**立刻点一次验证**。

点了没反应或者跳错地方，说明：
- 点的是"文字"而不是"那一行"（很多列表要点头像或右侧空白）
- 或者页面还没加载完（先 `wait 1500` 再 `read`）
- 或者那个元素其实是容器，真正可点的是它的子节点

## 第五步：找输入框的四个套路

搜索框是最常打交道的元素，也是最容易卡住的地方。按顺序试：

1. **点一下它再输入**：多数 App 的搜索框点开后会换成另一个真正的 EditText，
   直接写是写不进去的。先 `click`，再 `input`（不要带 target）。
2. **target 写提示文字**：空输入框的 `text` 是空的，提示词在 `hint` 里。
   小红书搜索框读出来是 `EditText「搜索, 咖啡」hint=「小红书头像」`，
   写 `target:"搜索"` 能命中，写 `target:"小红书头像"` 也能命中。
3. **别用 n 编号当 target**：`n7` 这种编号只在这一屏有效，页面一变就对不上，
   会报「未找到输入框: n7」。要用就用文字或 id。
4. **实在找不到就 `input` 不带 target**：会写进"当前焦点框"，
   如果上一轮刚点过输入框，这条基本必成。

### 键盘弹出来之后有个坑

输入法一弹，**当前活动窗口可能变成输入法窗口**，那里面一个输入框都没有，
于是"明明看到搜索框却报未找到输入框"。2026-10-31 已修（会同时遍历应用窗口），
如果你还遇到，先 `back` 收起键盘再重试。

## 第六步：沉淀成技能（重要）

摸清之后**一定要存下来**，下次直接读，不用再摸：

```
skill {"action":"create",
  "name":"某某App",
  "description":"一句话说明这个技能解决什么问题",
  "scope":"app",
  "appName":"App名字",
  "appPackage":"包名（从 app_list 拿）",
  "triggers":["app名","常见说法1","常见说法2"],
  "content":"## 完整路径\n...\n## 关键元素\n表格\n## 坑\n..."}
```

技能正文写三块就够：

1. **完整路径**：从打开到目标，一行一个箭头
2. **关键元素**：资源 id / 文字 / 大概位置
3. **坑**：你实际踩到的（点错、弹窗、加载慢）

**坑最值钱**。下次遇到同类问题，一句"点右侧空白才进得去"能省十步。

## 通用判断原则

- **看到的才算数**：树里没出现的元素就是不存在，不要凭想象去点
- **不确定就 read**：读一次屏幕比瞎点三次快
- **一次只做一件事**：页面会变的时候少给动作
- **失败两次就换思路**：同一个位置点两次没反应，换元素或换路径，不要重复
- **报错要读懂**：系统会说"点击成功但页面没变化"，这通常意味着点到了非目标元素
