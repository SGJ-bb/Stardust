# 界面自动化通用流程

## 一、先花一秒判断：能不能拿到界面结构

| 现象 | 结论 |
| --- | --- |
| 能拿到元素（有文字、有坐标、有层级） | 优先用结构定位，最快最准 |
| 结构是空的，但截图能看清 | 这个 App 屏蔽了结构，只能靠截图识别 |
| 两者都不行 | 才考虑让视觉模型看截图 |

**结构定位永远优先**：零延迟、能直接触发点击、不受界面动画影响。
截图识别是兜底，代价是慢（一次 1–3 秒）且有识别误差。

## 二、结构里没有时：截图识别文字

流程是「截图 → 识别文字 → 按坐标点」。要点：

1. **点之前先收起软键盘**。键盘上的候选词会被识别成普通文字，
   搜什么词就正好在键盘上出现什么词，于是你以为点的是列表，其实点在键盘上。
2. **排除屏幕最顶部的窄条**（状态栏、标题栏、搜索框）。
   搜索框里的字就是你要搜的词本身，不排除会一直点到搜索框。
3. **识别会有形近字误差**（繁简、异体、相似字）。
   匹配时允许「长度相同、只有一个字不同」，否则永远匹配不上。
4. **候选要按屏幕位置从上到下排**，不是按字面是否完全相等排。
   列表本身是从相关到不相关排列的，位置比字面更可信。

## 三、同一个词出现好几处：点哪个

先按匹配强度分档，再按位置排序：

```
文字完全相等  >  描述完全相等  >  只是包含
```

**「描述」这一档要往后放**：列表项的头像/图标往往文字为空、描述却写着名字，
先点它就变成「打开详情/资料卡」，而不是「进入这一行」。

## 四、点哪里才算点中

文字被点中 ≠ 这一行被点中。同一个位置可能分成几个不同的响应区：

- **文字中心**：按钮类（发送、确定、搜索）点这里
- **文字右侧的空白**：列表行点这里最稳（左边往往是头像，中间是不可点的文本）
- **文字左侧一个行高**：兜底

所以不要只试一个点，**失败就换下一个落点**。

## 五、点完必须确认

点了不代表生效。判断依据二选一：

- 当前页面（界面标识）变了
- 界面内容版本号变了

**都不能用「界面看起来变了」当判据**——点击本身也会触发一次高亮/选中，容易误判成功。
确认失败就重来一次，重来时重新截图（界面可能已经动过了）。

## 六、界面会在你算坐标的这几百毫秒里动

最常见的两种：

- 顶部弹出新消息横幅，把整个列表往下推
- 列表自己在刷新/加载

所以：**算坐标和点下去之间隔得越久，越容易点空**。
点空了不是「元素不存在」，重来一遍往往就好了。

## 七、输入文字

- 中文**不要**用命令行注入（只吃英文数字，中文会丢）
- 先点一下输入框让它获得焦点
- 用「写剪贴板 + 粘贴」的方式把中文送进去

有些输入框接受「直接设置文本」并返回成功，但实际什么都没写进去——
**要回读一次确认**，不能只信返回值。

## 八、什么时候该停

同一处连续试 2–3 次都没反应，就停下来告诉用户：
「我能看到这个界面，但这一行点不动」。
不要无限重试，也不要把「点了但没反应」说成「已经完成」。
