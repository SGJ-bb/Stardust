# 不同 App 的界面可读性

## 一、先看两个数，判断这次到底读到没有

抓到界面结构后，先确认这两个数：

- **最大层级（depth）** ≥ 15
- **带文字的节点数** ≥ 5

两个都满足，说明读到了，可以正常用结构定位。
**任何一个不满足，就别拿这份数据下结论**——不是这个 App 不能读，可能是下面四种情况之一。

## 二、四种情况，四种处理

### 1. 读到了（正常）

主流 App 基本都在这类：聊天、短视频、地图、浏览器、电商。
节点数几十到一百多，文字节点占大头。按平时的方式找元素、点。

### 2. 节点极少（个位数），但界面明明很丰富

特征：只有 3–10 个节点，几乎全是一个大容器，文字很少。

这说明这个 App 用的是**自绘渲染框架**（Flutter / Compose 一类），整屏是一个画布，
系统只能看到一个空壳。这类**调深度没有用**，直接走截图识别。

别在这里反复试不同参数，浪费的是用户的时间。

### 3. 只有两个节点，页面上写着"输入密码访问"

这是手机系统的**应用锁**（保护隐私的功能）。

不是 App 有问题，也不是读不到——是被锁了，需要用户自己输密码。
**这时候应该停下来告诉用户**："这个 App 有应用锁，我打不开，需要你自己解锁一下"。
不要去猜密码、不要去试。

### 4. 只是页面不对

常见三种：
- 停在**启动页/广告页**（还没进主界面）
- 停在**登录页**（没登录，只能到这一步）
- 被**弹窗/权限请求**挡着（先关掉弹窗）

判断方法：看当前页面的名字。
- 名字带 Login / 登录 → 卡在登录
- 名字带 Splash / Welcome → 卡在启动页
- 名字带 Dialog / 弹窗 → 有弹窗挡着

处理：等一会儿再看，或者先把弹窗关掉（找"取消""以后再说""跳过"），再重新读。

## 三、要读多深

有的 App 层级特别深（聊天列表的会话名可能在二十多层）。
所以**读界面时一律用最大深度**，不要为了省时间只看前几层——
省下来的那点时间，换来的是"看起来读了其实什么都没读到"，代价大得多。

## 四、什么时候该承认失败

同一个界面，按"结构定位 → 截图识别"两级试过都没成，就停下来告诉用户：
「这个界面我读不到内容」。

不要：
- 反复重试十几次
- 把"点了一下"说成"已完成"
- 猜一个看起来像的地方就点
