# 记忆系统：按人脑记忆机制重构

> 更新时间：2026-10-24
> 代码：`memory/TieredMemory.kt`、`memory/MemoryConsolidator.kt`
> 测试：`app/src/test/.../TieredMemoryTest.kt`（13 项，全通过）

---

## 一、为什么不是"全存着"或"全压掉"

原来的做法只有一个旋钮：**字符数超限就整体重排压缩**。这带来两个直观的毛病：

- 刚说过的话可能被压掉（因为它不区分新旧，只按容量裁）
- 一周前的小事和上周的约定一样清楚（因为没有时间维度）

人脑不是这么工作的。心理学里有几条比较硬的结论，直接决定了这次的设计：

| 现象 | 结论 | 落到代码 |
|---|---|---|
| 多存储模型（Atkinson–Shiffrin） | 记忆分层，细节逐级丢失 | 情景 → 要点 → 语义三层 |
| 遗忘曲线（Ebbinghaus） | 强度随时间指数衰减 | `strength = exp(-t / S)` |
| 间隔重复 | 每次回忆都延长保持时间 | 回忆一次 `S × 1.6` |
| 系统巩固（Squire & Alvarez） | 海马体细节 → 皮层抽象，需要时间 | 7 天 / 30 天两个巩固节点 |
| 情绪唤醒增强记忆 | 重要的事忘得慢 | `importance` 参与稳定性计算 |

## 二、三层分别留什么

| 层 | 龄期 | 留下什么 | 实际效果 |
|---|---|---|---|
| **情景记忆**（EPISODIC） | 0–7 天 | 原始细节 | "昨天下午你说要去医院复查" |
| **巩固记忆**（CONSOLIDATED） | 7–30 天 | 压缩成要点 | "上周他去医院复查了，结果还好" |
| **语义记忆**（SEMANTIC） | 30 天以上 | 抽象成稳定事实 | "他怕打针" |

关键点：**层的差别不是"存在哪"，而是"还留多少细节"**。

原文不会被删。被巩固的条目标记 `archived=true`，仍可检索溯源（"这话是哪天说的"），只是不再主动注入上下文。

## 三、强度怎么算（这是核心）

只按"多久以前"分层是不够的：三天前的小事该记住，而半年前反复提起的事不该被当成模糊记忆。

```
strength = exp(-elapsedDays / stability)

stability = 4天
          × 1.6^回忆次数      （间隔重复，最多放大 24 倍）
          × (1 + 1.5×重要性)   （重要的事衰减更慢）
```

三个可验证结果（都有单元测试钉住）：

| 场景 | 结果 |
|---|---|
| 刚发生 | strength ≈ 1.0 |
| 8 天前、没被提起过、不重要 | 掉到 0.2 左右 |
| 8 天前、但被提起 5 次 | 仍然 > 0.5 |
| 语义层（长期印象） | 不参与衰减，恒 ≥ 0.85 |

强度低于 0.15 就不主动注入上下文，但条目还在库里，能搜到。这就是"忘了细节但记得有这么回事"。

## 四、巩固在什么时候跑

**不按轮次、不按容量，按龄期。**

```
对话中每 N 轮评估记忆（原有逻辑）
        ↓
   顺手检查有没有到龄期的记忆
        ↓
有 → 后台线程调一次 AI 压缩（不阻塞聊天）
无 → 什么也不做，零成本
```

人脑的巩固发生在空闲和睡眠期，不是正在说话的时候。所以这里也是 fire-and-forget 的后台任务。

两个阶段：

1. **7 天以上情景记忆 → 要点**：要求 AI "只留答应过的事、做过的决定、情绪转折、新出现的人"，明确禁止编造。
2. **30 天以上要点 → 长期印象**：抽"偏好 / 习惯 / 关系 / 敏感点 / 长期目标"，要求"只写长期成立的，不写具体某天"。

**失败绝不改数据**：AI 调用失败或解析失败就原样返回，不会出现"压缩失败把记忆清空"这种情况。

## 五、注入给 AI 的模样

```
【关于他/她的长期印象】（稳定事实，不是某天发生的事，可直接用）
· 他怕打针
· 他喜欢在深夜写代码

【过去一段时间的要点】（细节已模糊，只有结论；不要编造过程细节）
· 上周｜约好周末一起看电影，后来因为加班改期了

【最近发生的事】（细节清楚，可以具体引用）
· 今天｜加班到十点，说很累但项目上线了
· 2天前｜提到想换个键盘
```

每段都带一句"怎么用"的说明——模型最容易犯的错是把早期摘要当细节编造，或者把最近的事说得含糊。

预算按信息密度倒挂分配：语义 25% / 要点 35% / 近期 40%。

## 六、界面上能看见

记忆池页面（设置 → 记忆池 → 场景记忆）：

- 统计卡多了一行「分层：情景 12 · 要点 5 · 长期印象 8」
- 列表按三层分组，每组带说明：
  - **最近 · 记得细节**（7 天内的事，能具体回忆）
  - **要点 · 细节已模糊**（7~30 天，只留结论）
  - **长期印象 · 稳定事实**（30 天以上，抽象成对人的了解）
- 每条右上角有清晰度标签：清晰 / 记得 / 模糊 / 依稀 / 淡忘

## 七、测试怎么保证没写歪

`TieredMemoryTest` 13 项，跑在 JVM 上（不需要设备）：

```
./gradlew testDebugUnitTest --tests "com.aicompanion.memory.TieredMemoryTest"
tests=13 failures=0 errors=0
```

钉住的都是"界面上看不出来、但会让人设崩塌"的点：

- 时间窗算错一天（6 天算不算该巩固）
- 遗忘曲线符号反了（越旧越清晰）
- 归档条目又被塞回上下文
- 预算失控（一条记忆把上下文吃满）
- 旧数据缺字段时丢内容（升级兼容）
- 序列化往返丢分层信息

## 八、还差什么

1. **真实巩固没跑过**：逻辑验证完了，但"AI 真的能把 7 天前的 15 条压成 3 条要点"这件事需要真实数据 + 联网跑一次。等红米插上、聊几天再看。
2. **`search_memory` 没接强度**：现在检索还是关键词/向量，没按强度排序，也没在命中时强化（`markRecalled` 已备好，未接线）。
3. **巩固粒度**：目前一批最多 15/20 条，大量历史数据首次升级会需要多轮，可以加个"批量追赶"的进度提示。
